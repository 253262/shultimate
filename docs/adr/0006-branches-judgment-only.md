# ADR-0006：「如果当时」只对判定题开放

- 状态：已采纳
- 日期：2026-10-20
- 相关：`app/generator.py` `is_judgment_question`、`/api/branches`、AGENTS.md §2.0.0

## 背景

「如果当时」第一版对所有问题开放。实测发现两类坏结果：

1. 情绪题「今天被打爆了，心情不好，规则上我该怎么调整」
   推演出「主动去跟对方队员打个招呼」——这是精神建议，不是规则推演。
2. 流程题「开盘盘没飞过中线在哪捡」推出「另一条相关规则」，
   不是"同一个瞬间的另一个选择"。

## 决策

- 只有**判定题**（"算不算 / 算吗 / 怎么算 / 算不算出界"）才显示按钮
- 服务端 `/api/branches` 用 `is_judgment_question` 再挡一次
- 每条岔路必须绑定给定 `clause_id`；绑不上就丢弃
- 条款原文由服务端按 id 从语料取，不信任客户端传来的文本
- 最多 3 条；标签写死「推演，不是判罚」

## 后果

- ✅ 不会变成豆包式关心，也不会把"相关规则"伪装成"另一个选择"
- ✅ 判定题的岔路质量明显更高（实测 7/7 出岔路，0 条伪造条款）
- ⚠️ 流程题没有这个按钮；用户可能问"为什么这题没有"
- ⚠️ 判定题也可能推不出岔路（如实返回"这一步没有可推演的岔路"）
- ⚠️ 需要持续用 golden set / 人工抽检盯住"条款讲的是不是同一个动作"

## 被否决的替代方案

- **对所有问题开放**：实测会产出精神建议/相邻规则
- **让模型自由发挥**：违背"零编造"红线
