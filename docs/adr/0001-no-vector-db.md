# ADR-0001：不用向量数据库，全量点积

- 状态：已采纳
- 日期：2026-10-12
- 相关：`app/retriever.py`、AGENTS.md §5

## 背景

语料只有 474 条（368 规则 + 40 定义 + 5 前言 + 61 附录），
2048 维向量约 3.7MB。一次全量点积实测约 60ms。

## 决策

不引入 FAISS / Milvus / pgvector / Elasticsearch。
启动时把向量读进内存，查询时做全量点积 + 关键词/族加分。

## 后果

- ✅ `clone` 即跑：不需要额外服务、不需要 Docker、不需要账号
- ✅ 没有"索引和数据库不一致"这一类故障
- ✅ 排序逻辑完全在代码里，评测和线上共用同一份打分（单一真源）
- ⚠️ 语料涨到 1 万条以上会开始疼（60ms × 20）；到那天再换，不提前优化
- ⚠️ 每次改语料都要重建 `embeddings.bin`，不能热更新

## 被否决的替代方案

- **FAISS**：多一个二进制依赖，且要维护索引文件版本
- **pgvector**：多一个数据库，和"零运行时依赖"直接冲突
- **Elasticsearch**：运维成本远大于收益
