# ADR-0005：复盘页是默认落地页

> **状态更新（2026-10-23）**：本 ADR 记录 2026-10-20 的历史决定，不再是当前入口依据。
> 当前空 hash 启动实际落 `#/chat`，最终入口待 Owner 按用户证据裁决；
> 产品目标以 [`docs/product.md`](../product.md) 为准。以下正文保留当时记录。

- 状态：历史决定（2026-10-23 产品准则校准后不再作为当前入口依据）
- 日期：2026-10-20
- 相关：`static/app.js` `parseHash`、`viewReplayPage`、AGENTS.md §2.0.0

## 背景

owner 2026-10-20 明确：

> 「这个产品一定不是在场上打比赛的时候拿出来，而是复盘的时候再拿出来用的。」
> 「在场上你打比赛，你怎么可能掏出个手机、掏出个电脑去做这个事情？」

原来的默认页是对话（`#/chat`）：一个聊天框 + 三条示例问题。
它把产品框成"随时问一句的 AI 助手"，而不是"赛后复盘的工具"。

## 决策

- 默认落地页改为 `#/replay`
- 第一屏只有一个输入框：无问候、无示例、无"猜你想问"
- 对话保留为 `#/chat`，入口收成右上角「问一句」
- 回答是一张**判定卡**（结论 / 条款 / 下次 / 原文），不是聊天气泡
- 点「摆到场上」才展开球场；位置只帮回忆，不参与判定

## 后果

- ✅ 产品身份从"聊天助手"变成"复盘工具"
- ✅ 首屏没有"招商式"内容，用户带着问题来就能直接问
- ⚠️ 新用户第一次打开看不到"这是什么"——只靠 placeholder 和一行信任说明
- ⚠️ 聊天页的示例/大标题已删（2026-10-20），别再搬回来
- ⚠️ **2026-10-22 更新**：owner 看预览后要求**恢复聊天页的介绍**
  （标题 + 依据说明 + 3 条入口示例），原话「点进去只是个大白板，太难看了」。
  ⇒ 本 ADR 的「无示例」只适用于**复盘页第一屏**；聊天页可以有 3 条示例，
  但必须「点了只填入、不直接发送」，且不许放情绪推荐。见 `docs/product.md`。

## 被否决的替代方案

- **保留 chat 为默认**：和"复盘"的定位冲突
- **做一个 landing page 解释产品**：用户不是来读说明书的
